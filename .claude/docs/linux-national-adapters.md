# Linux National Adapters

## Ownership

National adapters are read-only inputs to `linux_system_adapter_deployment`, `linux_system_adapter_stewardship`, and `linux_system_adapter_assurance`. They never write native focus, idea, flag, variable, event, or corporate-system state. The shared recalculation clamps every numeric adapter to -2 through 2.

All national native adapters are disabled when Corporate History is Off. Their historical Linux base route remains available because the Linux rule owns that route. A monthly bounded-array recovery pass recomputes adapter values, compares them with the prior values, and marks Linux state dirty only when an adapter changed. Persistent ideas are therefore refreshed only after an actual state change.

No adapter assigns a support model. In particular, Munich's municipal LiMux deployment does not create a country-wide National Baseline, and Venezuela's training focus does not establish a maintenance regime. CHI does not read OpenHarmony or Android-compatibility state: those outcomes are not treated as an openEuler or Linux distribution result.

POL milestone 2 is suppressed only while Corporate History is enabled and the native 2008 software event carries `POL_industrial_sovereignty_event_05_scheduled` or `POL_industrial_sovereignty_event_05_resolved`. A scheduled native delivery blocks the duplicate popup but does not advance the Linux milestone early. Once the native route resolves on or after the 2008-06-01 milestone, Linux clears its owned delivery markers, adds the generic state-only Deployment +1 progression, and preserves earlier Stewardship, Assurance, and support choices. The native route supplies the bounded read-only adapter.
